## Decisions

| Topic | Decision | Why |
|---|---|---|
| Journal | WAL + `synchronous=FULL` + `fullfsync=ON` (+ `checkpoint_fullfsync`) | COMMIT returns only after the WAL is fsynced (FULL is durable across power loss; NORMAL in WAL is not). UI/CLI readers never block engine commits (a rollback-journal reader holds SHARED and would make engine commits hit `SQLITE_BUSY` -> DEGRADED). `fullfsync` makes macOS flush the drive cache. Local filesystem only. |
| Types | every table `STRICT`; only `TEXT`/`INTEGER` columns; decimals canonical TEXT (never rounded), ids TEXT, CID INTEGER; float and Decimal SQL params refused at the connection wrapper | AC-22; `NUMERIC` affinity would silently coerce decimal strings. |
| Append-only / immutable | triggers abort UPDATE/DELETE of `cid_map`, `dedupe_keys`, `fills`, `audit_events`, `schema_migrations`, `config_revisions`, `baseline_adjustments`, delete of legs/cycles/cells/grids/outbox/inbox/conflicts; bootstrap fields, grid dimensions/Q/anchor, cell prices/sides and leg requests are immutable | no reset path exists even through a bug; baseline cannot be recaptured. |
| Single writer | `flock` on `~/.hummingbot/neutral_grid/locks/neutral_grid.<domain>.<account>.<pair>.lock` (host-wide, independent of the checkout's `data_path`; `$HUMMINGBOT_NEUTRAL_GRID_HOST_DIR` overrides) **and** `<db>.lock`, plus `engine_owner` row re-checked inside every write transaction (fencing). Foreign-host owner row refused unless `takeover_foreign_host=True` (audited). **Not a distributed lock** (module + class docstrings). | NG-DB-001. |
| Other processes | `open_readonly` (`mode=ro` + `query_only`), `open_command_client` (SQLite authorizer: INSERT into `commands` only) | UI reads committed snapshots, writes only commands. |
| Schema | v2 = `m0001_initial` + `m0002_attempts_and_gaps` (`outbox_attempts`, `cursors.retention_gap_open`); `schema_migrations` (version, name, sha256) + `user_version` + `application_id`; unknown/newer/edited/gapped history refused; pending migrations applied one tx each with audit **after** identity/marker/fingerprint checks | fail-closed migrations. `m0001` is frozen; add `m0002_*`. |
| CID | `cid = cid_epoch << 40 | seq` (< 2**48); `cid_map` append-only, identity UNIQUE; exhaustion -> `CidExhaustedError`; own-map or foreign collision (`foreign_cids`, history, caller check) -> `CidCollisionError`, cleared only by audited `retire_cid` | AC-43; a database recreated after loss gets `epoch+1` so lost CIDs are never reused. |
| Outbox protocol | intent tx -> `mark_dispatching` tx -> transport -> `record_transport_result` tx. A result other than NOT_SENT for a never-dispatched row is refused. PENDING after restart = provably unsent; DISPATCHED = unknown (leg SUBMIT_UNKNOWN). | narrows the ambiguous window without claiming exactly-once placement (NG-DB-002). |
| History | `apply_history_batch` = inbox rows + canonical dedupe keys + exact-ID fill attribution + ledger transitions + cursors in the caller's tx; conflicts are durable rows (`history_conflicts`) | NG-HIST-002, AC-19/40. |
| Store-level guards | ENTRY intents blocked by manual-reconcile flag, open conflicts, unmatched post-cut trades, degraded store; one physical entry per cycle; TP only up to history-confirmed E (`X + reserved TP + new <= E`); fixed side/price per role; LIVE/TERMINAL/REJECTED need venue evidence; cycle release needs all legs final, no reservation/outbox/dust/unallocated fill/late evidence and E == X | persistence-derivable safety net under WS-A/WS-D logic. |
| Degraded | any SQLite error -> `PersistenceError` (+ `StoreIntegrityError` for constraints), full rollback, `store.degraded_reason`; a degraded store refuses SUBMIT intents and any submit dispatch until `clear_degraded(actor, reason)` commits an audit row; cancel intents are allowed only if they commit | AC-55. |
| Prior run | markers `<db>.marker.json` + host marker `~/.hummingbot/neutral_grid/markers/<key>.marker.json` (outside any data dir; db_uuid, cid_epoch), leftover `-wal/-shm/-journal`, `prior_run_markers(identity, path)` callback; corrupt header/pages/foreign DB -> `StoreCorruptError`; `ManualRecovery` creates a new DB with new CID epoch, `manual_reconcile_required`, no baseline | AC-54. |

### API changes for WS-D / WS-E (all additive except where marked)

- Default lock/marker location is now host-wide: `default_host_dir()` = `~/.hummingbot/neutral_grid`
  (`$HUMMINGBOT_NEUTRAL_GRID_HOST_DIR` overrides; set it to a shared directory if several containers of one host may
  run the engine). `default_lock_dir(base_dir)` with an explicit base keeps the old layout; the host marker is
  `<lock_dir>/../markers/<key>.marker.json`.
- **Behaviour change** `mark_dispatching`: a DISPATCHED row (e.g. left by a dead process) is refused without
  `resend_same_cid=True`; never re-dispatch SUBMIT_UNKNOWN rows unless venue idempotence is documented (WS-C refuses a
  reused CID anyway). New read API `outbox_attempts(outbox_id)`.
- **Behaviour change** `record_transport_result`: NOT_SENT / DEFINITIVE_REJECT_ZERO_FILL finalise a submit only on the
  first attempt with no venue evidence; otherwise the attempt outcome is kept, the row's effective outcome is UNKNOWN,
  the leg keeps SUBMIT_UNKNOWN (or its evidenced state) and the reservation stays.
- **Behaviour change** transactions: a store call that raises *after writing* poisons the caller's transaction and
  COMMIT raises `PersistenceError`. Guards that refuse before writing (e.g. `EntryBlockedError` from
  `prepare_submit`/`record_intent`, TP headroom, allocation checks) do not poison, so they may be caught and the tick
  continued.
- `prepare_submit`/`record_intent`: ENTRY amount must equal the cycle's planned amount and may not carry allocations;
  allocation targets must share the TP side and fixed TP price. A released cycle accepts a TP only for its audited late
  obligation (`late_evidence == 2`, E > X).
- Late evidence: `load_state().late_cycles` / `late_obligation_cycles()` list released cycles with E != X or
  unacknowledged late evidence. `open_cycle` refuses a new generation of that cell until the obligation is covered, and
  refuses any new cycle while a history conflict is unresolved (`EntryBlockedError`).
- `set_leg_state(TERMINAL)` refuses an aggregate leg with unallocated fills — call `allocate_fill` first.
- **Behaviour change** `record_order_evidence(..., final=True)` raises `ValueError`; terminal rows only via
  `apply_history_batch` (inactive orders).
- Retention gap: `CursorUpdate` that stores a required boundary older than the oldest available history opens a
  durable gap (`CursorRecord.retention_gap_open`); `complete=True` is refused while it is open; `entry_blockers()`
  reports it; clear it with `record_manual_reconciliation(..., resolved_retention_gaps=["TRADES"])`.
- `order_dedupe_key` = `["ORDER", domain, account, market, exchange order id]` (same identity as WS-C's 4-tuple, which
  `apply_history_batch(dedupe_keys=...)` accepts); an order row without `order_index`/`order_id` raises `ValueError`.

## Handoff to WS-D (engine)

1. Open once per process (lock + host marker live in `default_host_dir()`, see Review fixes): `NeutralGridStore.open(None or path, EngineIdentity(connector_name, connector_domain,
   account_index, trading_pair), create_if_missing=<first run only>, prior_run_markers=<callable: e.g. venue has
   orders/trades with our CID epoch>, config_fingerprint=config.fingerprint())`. Catch `StoreLockedError`,
   `PriorRunEvidenceError`/`StoreCorruptError`, `ConfigMutationError`, `SchemaVersionError`, `IdentityMismatchError`
   -> do not trade. Default path: `default_db_path(identity)` under `hummingbot.data_path()`.
2. First bootstrap only: `store.bootstrap(None, BootstrapRecord(...))` after the operator confirms B; the store
   checks N+1 strictly increasing prices, cells matching prices and the anchor side rule. On restart use
   `store.engine()` / `store.load_state()`; never call bootstrap again (it raises).
3. Submit: `with store.transaction() as tx: store.open_cycle(...)` (new cycle) `; intent = store.prepare_submit(tx,
   leg, side=..., price=..., amount=..., order_type=...)`; commit; `with tx: store.mark_dispatching(tx,
   intent.outbox_id)`; commit; `port.submit(intent.request)` (unchanged CID); `with tx:
   store.record_transport_result(tx, intent.cid, result)`. `test_ng_store_support.submit_via_protocol` is the
   reference. After restart use `store.unresolved_outbox()`: PENDING may be dispatched (same request/CID, first
   send); DISPATCHED/UNKNOWN stay SUBMIT_UNKNOWN with reservation until history/active evidence or audited manual
   reconciliation; `mark_dispatching(..., resend_same_cid=True)` only with documented venue idempotence.
4. Cancel: `record_cancel_intent` -> `mark_dispatching` -> `port.cancel` -> `record_transport_result(...,
   kind="CANCEL")`. A cancel ack moves the leg to TERMINAL_UNKNOWN; the reservation stays until TERMINAL proof. If a
   leg becomes final while a cancel row is unresolved, record the cancel's result (NOT_SENT if never dispatched,
   else what transport returned / UNKNOWN) so the cycle can be released.
5. History: `apply_history_batch(tx, scan.new_trades + scan.new_orders (inactive/terminal rows only),
   [CursorUpdate(...)], ledger_transitions=callable(tx, result))`; the store computes canonical dedupe keys itself,
   `dedupe_keys=` (keyword) only cross-checks the caller's keys. Use `result.new_fills` for TP obligations in the
   same tx (TP intents must follow committed entry fills: the store refuses TP > E), `result.conflicts`,
   `result.late_fills`, `result.unmatched` for freeze/pause. Active orders: `record_order_evidence(tx, row)` then
   `set_leg_state(tx, cid, LIVE)`. TERMINAL: `set_leg_state(tx, cid, OrderState.TERMINAL)` only after your settlement
   policy (delay + repeated full scan); the store additionally requires the final row and cumulative equality.
6. Release: `cycle_release_blockers(...)` / `close_cycle(...)` then `open_cycle(...)` for the next generation.
7. Expect `EntryBlockedError` (with `.blockers`) and `InvalidTransitionError` from store guards; show them as
   blockers. On `PersistenceError`: DEGRADED, send nothing, keep counting known live orders; `clear_degraded` only
   after recovery.
8. Commands: at the start of a tick `with tx: cmd = store.claim_next_command(tx); ...apply...;
   store.complete_command(tx, cmd.id, CommandStatus.APPLIED|REJECTED|CONFLICT, result)`. Stale commands are turned
   into CONFLICT by the store. `engine_revision` changes only when `set_engine_state` changes the state (or
   `bump_engine_revision`) — do not bump per tick or every UI command will conflict.
9. Snapshots: `write_snapshot(tx, {"engine_state": ..., "reasons": [...], "summary": ..., "cells": ...})` in the
   same tx as the state it describes; the store assigns `snapshot_version`, revisions and `committed_at(_ms)`.
10. Extra engine state: `kv_set(tx, key, json)` / `kv_get(key)`. Crash points for engine code:
    `store.fault_point("before_transport" | "after_transport" | "engine.<name>")`.
11. Retention/audits: `mark_retention_gap`, `mark_manual_reconcile_required`, `record_manual_reconciliation`,
    `record_baseline_audit`, `retire_cid`, `migrate_grid` (quiescent grid only), `record_config_revision`
    (non-dimension changes).

## Handoff to WS-E (web)

- `NeutralGridStore.open_command_client(db_path)`: `enqueue_command(key, CommandKind, expected_config_revision,
  expected_engine_revision, payload)` returns a `CommandRecord`; `duplicate=True` on a repeated key (original row,
  never re-applied), `request_mismatch=True` if the retry differs. CONFLICT rows carry `current_config_revision`,
  `current_engine_revision`, `latest_snapshot_version` for the fresh preview. It cannot write anything else.
- `NeutralGridStore.open_readonly(db_path)`: `latest_snapshot()` -> `StoredSnapshot` (`snapshot_json` can be served
  verbatim; decimals/ids are strings, ints above 2**53 are strings); staleness from `committed_at_ms`.
  `get_command`, `list_commands`, `audit_events` are readable.
- Drill-down without truncation: `find_orders_by_id`, `find_fills_by_trade_id`, `commands_page`, `audit_page` (see
  "UI drill-down queries"); they replace scanning the newest 5000 rows.

## Open risks

- The lock is host-local (`flock`) and WAL needs a local filesystem; two hosts sharing the account are outside the
  guarantee (only the DB owner row detects a foreign host sharing the same DB file).
- Durability relies on the OS/drive honouring fsync (`F_FULLFSYNC` on macOS).
- "PENDING = unsent" holds only if engine code never calls transport before `mark_dispatching` commits; the store
  enforces the result side of that protocol, not the call itself.
- `degraded_reason` is in memory: when storage is full the engine cannot write a DEGRADED snapshot, so the UI must
  treat snapshot age as the failure signal; after restart the engine starts reconciling anyway.
- A CID collision with a foreign order is fail-closed and needs an operator `retire_cid` (epoch-prefixed CIDs make
  collisions with Hummingbot's random 48-bit ids unlikely, not impossible).
- The store detects and records a retention gap; deciding that the venue's history is shorter than the required
  boundary is WS-C/WS-D logic. Settlement delay/rescan before TERMINAL is WS-D logic.
- Snapshot JSON accepts floats for timestamps (money must be Decimal); `canonical_json` for ledger data refuses
  floats.
- `test_default_path_is_under_hummingbot_data_path` calls `hummingbot.data_path()`, which creates the (git-ignored)
  `data/` directory of the checkout.
