# Локальный веб-интерфейс нейтральной сетки

Спецификация: `docs/superpowers/specs/2026-09-24-neutral-grid-spec.md`, разделы NG-UI-001..003, §11, AC-46..AC-50.

## Запуск

Офлайн-демо (без ключей, без сети; движок работает на `FakeExchange` с временным SQLite):

```bash
python bin/lighter_robinhood_neutral_grid_web.py --demo-fake-exchange
```

Подключение к движку, который работает в процессе Hummingbot (web только читает зафиксированные снимки и
кладёт команды в очередь):

```bash
python bin/lighter_robinhood_neutral_grid_web.py --attach-db <путь к sqlite движка> --config <grid.yml>
```

Лаунчер печатает в терминал одну ссылку вида `http://127.0.0.1:8787/#auth=<токен>`. Токен передаётся во
фрагменте URL, поэтому он не попадает на сервер в строке запроса и не пишется в журналы. Это токен доступа к
локальной панели, а не ключ биржи. Закрытие или перезагрузка браузера не останавливает движок; сервер
останавливается по Ctrl+C, журнал движка при этом остаётся на диске.

## Граница безопасности (NG-UI-001, AC-49)

* По умолчанию сервер слушает только `127.0.0.1`. Не-loopback адрес отклоняется, пока не передан
  `--allow-non-loopback-bind`, и даже тогда печатается предупреждение.
* Каждый запрос проверяет заголовок `Host` (только имена loopback-адресов и реальный порт), чтобы закрыть
  DNS rebinding.
* Сессия: случайный cookie `ngw_session` с атрибутами `HttpOnly; SameSite=Strict; Path=/`. Сессии хранятся
  только в памяти процесса.
* Каждый изменяющий состояние запрос требует:
  * совпадающий `Origin`;
  * `Content-Type: application/json`;
  * заголовок `X-CSRF-Token`, равный токену сессии.

  Ответы: без сессии — 401, плохой или отсутствующий CSRF — 403, чужой Origin — 403.
* Заголовки: CSP только `'self'` (без inline-скриптов и стилей), `X-Frame-Options: DENY`, `nosniff`,
  `Referrer-Policy: no-referrer`, `Cache-Control: no-store` для API. Внешних CDN нет: все ассеты лежат в
  `static/`.
* Ключи: профиль выбирается по имени из существующего зашифрованного keystore Hummingbot
  (`conf/connectors/*.yml`). UI видит только признак «задано / нет» по каждому полю. Разблокировка вызывает
  нативный `Security.login(ETHKeyFileSecretManger(password))`. Пароль передаётся только в теле POST-запроса
  или вводится скрытым вводом в терминале (`--unlock-tty`). Он не принимается в аргументах, не пишется в
  журнал, не возвращается в ответах и не хранится в браузере. Эндпоинта для чтения секретов нет. Keystore из
  веба не создаётся. Формат API-ключа проверяется существующим валидатором мастера настройки: 80 hex, `0x`
  необязателен; 64-hex ключ кошелька не подходит.
* Браузер не получает учётные данные и никогда не обращается к бирже. Единственный путь записи — строка в
  таблице `commands` через `NeutralGridStore.open_command_client`. SQLite-authorizer этого подключения
  разрешает только `INSERT` в `commands`.

### Удалённый доступ (будущий серверный деплой)

Встроенная защита рассчитана на один локальный компьютер: TLS нет, а токен доступа — единственный фактор.
Для доступа с другой машины используйте SSH-туннель:

```bash
ssh -L 8787:127.0.0.1:8787 user@host
```

и открывайте `http://127.0.0.1:8787/…` локально. Другой вариант — обратный прокси с аутентификацией и TLS
перед loopback-сервером. `--allow-non-loopback-bind` без такого прокси небезопасен.

## Семантика команд (NG-UI-003, AC-47)

* Команда `POST /api/commands` содержит:
  * `kind`;
  * уникальный `idempotency_key`;
  * `expected_config_revision` и `expected_engine_revision` — ревизии, которые видел оператор;
  * `payload` — все числа строками.
* Повтор с тем же ключом и тем же запросом возвращает исходную строку команды (200). Тот же ключ с другим
  запросом даёт 422.
* Устаревшие ревизии — 409 со свежим превью; команда не ставится в очередь и не применяется автоматически.
  Хранилище повторно проверяет ревизии атомарно. Если движок успел продвинуться между проверками,
  хранилище записывает строку `CONFLICT`, и API тоже отвечает 409.
* Повторный или параллельный Start для той же идентичности возвращает 409 с существующей командой
  (`start_already_queued`) или идентичностью работающего движка (`engine_already_running`). Второй движок
  не создаётся. Это обеспечивают три механизма: asyncio-lock приёма команд, проверка «уже есть QUEUED
  start» в хранилище и host-lock хранилища на `(domain, account, pair)`. Движок, ожидающий старта
  (`AWAITING_START`), работающим не считается.
* Start требует:
  * повторно введённый оператором `expected_initial_position` — он должен совпасть с конфигурацией;
  * `baseline_acknowledged=true` и `risk_acknowledged=true`;
  * `preview_id` просмотренного превью. `preview_id` зависит от конфигурации, правил рынка и ревизий, но
    не от текущей цены.
* Ответ отражает зафиксированное состояние команды (`QUEUED`, затем `APPLIED`/`REJECTED`/`CONFLICT` от
  движка), а не предполагаемый результат на бирже.

## Честное состояние (NG-UI-002, AC-48)

* Показывается только `engine_state` последнего зафиксированного снимка.
* Нет снимка — «Нет данных».
* Снимок старше `--stale-after` секунд (по умолчанию 15) — «Нет свежих данных», последнее известное
  состояние показывается отдельно.
* Факт «процесс backend жив» выводится отдельно (`host`) и никогда не превращается в `NORMAL`.
* Состояние ячеек берётся из снимка и не выводится из текущей цены.

## Точность чисел (AC-22, UI)

Все десятичные значения и все ID передаются строками. Слой `jsonsafe` дополнительно превращает любые
целые за пределами ±(2^53−1) и id-поля в строки. `app.js` не использует `Number()`, `parseInt` и
`parseFloat` и не выполняет арифметику над количествами; полосы шкал рассчитываются на сервере в `Decimal`.
Поиск по ID сравнивает строки точно.
